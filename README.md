# Стриж

Кроссплатформенный Jabber-клиент: один статический фронтенд на SvelteKit,
десктоп в Tauri, мобильные в Capacitor. Сообщения идут напрямую между
устройством и вашим XMPP-сервером — посредника-бэкенда у приложения нет.

Тип репозитория: мультипакет (apps/ + packages/)

## Что умеет

| Возможность | Состояние |
| --- | --- |
| Вход по JID и паролю, свой WebSocket-эндпоинт | есть |
| Добавление и удаление контактов, заявки на подписку | есть |
| Ростер и присутствие контактов (RFC 6121, §2.5 push) | есть |
| Личные сообщения с подтверждением доставки (XEP-0184) | есть |
| Индикатор набора (XEP-0085) | есть |
| Время сообщения из `<delay>` (XEP-0203) | есть |
| Смена присутствия и статусного сообщения | есть |
| Несколько сохранённых учётных записей на устройстве | есть |
| Группы контактов (roster groups) | не сделано |
| Шифрование пароля в keychain устройства | не сделано, см. «Долги» |
| MUC, архивы (MAM), шифрование OMEMO, вложения | не сделано |

## Раскладка

```text
strizh/
├── Makefile                  единственная точка входа
├── scripts/                  исполняемые скрипты корня (раздел 1 скилла)
├── apps/
│   ├── web/                  SvelteKit 3 + adapter-static → build/
│   │   ├── Makefile          свой раннер: vite dev/build, svelte-check
│   │   ├── scripts/
│   │   ├── src/routes/       экран входа и мессенджер
│   │   └── src/lib/          компоненты, состояние, платформа, хранилище
│   ├── desktop/              Tauri 2: оболочка поверх apps/web/build
│   │   ├── Makefile
│   │   ├── scripts/
│   │   └── src-tauri/        Cargo-крейт, tauri.conf.json, иконки
│   └── mobile/               Capacitor 8: Android-проект поверх apps/web/build
│       ├── Makefile
│       ├── scripts/
│       └── android/          сгенерированный gradle-проект
└── packages/
    └── xmpp-core/            XMPP-ядро: соединение, ростер, сообщения, типы
```

Направление зависимостей: `apps/web → packages/xmpp-core`. Нативные оболочки
не зависят от JS-пакетов — они загружают уже собранный статический бандл.

## Быстрый старт

```console
$ make install                 # одна установка, один lockfile, из корня
$ make dev                     # http://localhost:5173
```

Без селектора поднимается только фронтенд. Так сделано намеренно: desktop и
mobile — оболочки над тем же Vite-сервером на порту 5173, и «все приложения
сразу» означали бы три процесса, дерущихся за один порт. Оболочки стартуют по
имени: `make dev ARGS="desktop"`, `make dev ARGS="mobile"`.

Проверка без реального сервера: в репозитории есть мок XMPP-сервера.

```console
$ bun packages/xmpp-core/test/mock-server.ts      # ws://127.0.0.1:5280/xmpp-websocket
```

Учётки `anna`, `boris`, `vera` @localhost, пароль любой. В браузере на экране
входа раскройте «свой сервер» и укажите `ws://127.0.0.1:5280/xmpp-websocket`.

## Команды

| Команда | Что делает |
| --- | --- |
| `make install` | установка зависимостей (bun, из корня) |
| `make dev` | Vite dev-сервер фронтенда (умолчание) |
| `make dev ARGS="desktop"` | `tauri dev`: окно с WebView и горячей перезагрузкой |
| `make dev ARGS="mobile"` | запуск на подключённом Android-устройстве |
| `make build ARGS="web"` | статический бандл в `apps/web/build` |
| `make build ARGS="desktop"` | бинарник Tauri (без установщиков) |
| `make bundle ARGS="desktop"` | установщики локально: `.deb`, `.rpm` |
| `make release ARGS="0.2.0"` | релиз: проверки, тег, сборка на трёх ОС в CI |
| `make build ARGS="mobile"` | debug-APK |
| `make check` | svelte-check + конфиги оболочек |
| `make test` | тесты всех юнитов |
| `make check-runner` | контракт `scripts/` + `Makefile` |
| `make monorepo-check` | раскладка `apps/` + `packages/` |

Цели юнитов работают и напрямую: `make -C apps/web build`.

## Релиз

```console
$ make release ARGS="0.2.0 --dry-run"   # проверки и тег локально, без отправки
$ make release ARGS="0.2.0"             # тег v0.2.0 → push → CI собирает и публикует
```

Сборка артефактов идёт в GitHub Actions (`.github/workflows/release.yml`), а
не локально: одна машина не даёт три платформы. По тегу `v*` workflow сначала
прогоняет проверки, затем параллельно собирает:

| ОС | Артефакты |
| --- | --- |
| Linux (ubuntu-22.04) | `.deb`, `.rpm` |
| Windows | `.msi`, `.exe` (NSIS) |
| macOS (aarch64 и x64) | `.dmg` |

Версия попадает в `tauri.conf.json` из имени тега прямо в CI — правку конфига
коммитить не нужно. Тег с дефисом (`0.2.0-rc.1`) публикуется как prerelease.

Сборка macOS не подписана: Gatekeeper покажет предупреждение при первом
запуске. Для подписи нужны сертификаты Apple Developer и секреты
`APPLE_CERTIFICATE`, `APPLE_SIGNING_IDENTITY` в настройках репозитория.

## Требования

- bun ≥ 1.4 (установка и скрипты)
- Node ≥ 22 (тесты, `node --test`)
- Rust ≥ 1.77 и системные dev-пакеты — только для десктопа
- Android SDK 36, JDK 21 — только для мобильных

### Десктоп

```console
$ sudo apt install libwebkit2gtk-4.1-dev libgtk-3-dev libsoup-3.0-dev \
                   libdbus-1-dev librsvg2-dev build-essential
```

Если Rust ставится через asdf, версия должна быть назначена: репозиторий
содержит `.tool-versions` со строкой `rust 1.99.1`. Без неё шим `cargo`
существует, но падает с кодом 126, и Tauri не может выполнить `cargo metadata`.

`make -C apps/desktop dev` проверяет и тулчейн, и наличие всех пяти
библиотек через `pkg-config` до запуска сборки: иначе cargo честно соберёт
240 крейтов и упадёт на `libdbus-sys` через пять минут.

### Мобильные

`scripts/dev` сам подставляет `ANDROID_HOME` и `JAVA_HOME`, если они лежат в
`~/android-build/`, и проверяет наличие устройства через `adb devices`. Без
устройства запуск бессмысленен — для проверки сборки есть `make build ARGS="mobile"`.

## Платформа и ресурс

Один и тот же бандл определяет, где он запущен (`src/lib/platform.ts`), и
подставляет разный XMPP-ресурс: `strizh-web`, `strizh-desktop`,
`strizh-mobile`. Это важно: с одинаковым ресурсом сервер выбивает прошлую
сессию того же пользователя.

## Транспорт и поиск эндпоинта

Только WebSocket (RFC 7395): TCP/TLS недоступен из WebView. Поле «свой сервер»
на экране входа можно оставить пустым — тогда клиент найдёт адрес сам:

1. XEP-0156: `https://<домен>/.well-known/host-meta.json`;
2. типовые адреса: `:5280/xmpp-websocket`, `/ws/` на 443-м, `/xmpp-websocket`;
3. перебор по очереди, 8 секунд на кандидата.

Проверено на `jabber.ru`: он объявляет `wss://jabber.ru:443/ws/`, а порт 5280
закрыт файрволом — вход занимает меньше секунды. Явно указанный адрес не
перебирается: человек знает, что делает.

Ошибки показываются текстом, а не пустой строкой: «Неверный логин или пароль»,
«Сервер … не ответил за 8 секунд».

## Долги

Записаны, чтобы не выглядеть готовыми:

1. **Пароль в localStorage без шифрования.** Нужен платформенный keychain:
   Tauri Stronghold и Capacitor Preferences + biometric.
2. **Нет оффлайн-очереди.** Сообщение, отправленное без соединения, теряется.
3. **Нет истории на диске.** Переписка живёт в памяти вкладки; после
   перезагрузки остаются только черновики.
4. **Нет OMEMO.** Трафик шифруется только TLS-транспортом до сервера.
5. **Десктопная сборка проверена, но через шимы `pkg-config`**: в среде нет
   dev-пакетов, поэтому `scripts/_pkgconfig.sh` подставляет `.pc` сам. Бинарник
   собирается и открывает окно; для релиза нужны настоящие dev-пакеты.
6. **Мобильная сборка проверена как APK**, установка на устройство и
   iOS-сборка — нет.
